FPGA Digital Communications Board Test 08: Tracker Frame Encoder
===========================================

Goal
----

Move from reporting OFDM counts to generating the actual compact tracker frame
shape on the Nexys Video FPGA.

The FPGA builds the tracker payload, wraps it with the shared frame fields, and
computes CRC-8 over:

```text
length byte + 129-byte compact tracker payload
```

This is the next bridge between the renewable tracker data and the digital
communication chain.

Vivado board code
-----------------

```text
Board:
  Digilent Nexys Video 410-316

Vivado part code:
  xc7a200tsbg484-1

Top module:
  tracker_frame_encoder_top

HDL sources:
  fpga-digital-communications/code/hdl/uart_tx.v
  fpga-digital-communications/code/hdl/crc8_byte.v
  fpga-digital-communications/code/hdl/tracker_frame_encoder_top.v

Constraints:
  fpga-digital-communications/hardware/constraints/nexys_video_tracker_frame_encoder.xdc
```

Generated compact payload
-------------------------

```text
trk,seq=00001,pan=124.9,tilt=102.6,sun_pan=127.0,sun_tilt=102.8,err=002.1,st=lock,v_mv=05506,i_ma=00421,p_mw=02318,src=ina,act=sw
```

Frame format
------------

```text
preamble:
  A5 5A

length:
  129 decimal / 0x81

payload:
  129 ASCII bytes

crc:
  CRC-8 over length + payload
```

Expected UART report
--------------------

```text
p1fe,seq=00001,payload=trk,pay_b=00129,frame_b=00133,pre=A55A,crc=XX,crc_ok=1,ok=1
```

Notes:

```text
crc changes when seq changes, so do not expect a fixed crc value.
crc_ok=1 and ok=1 are the pass indicators.
```

LED behavior
------------

```text
LD0:
  CRC OK.

LD1:
  Heartbeat toggles once per report.

LD2:
  UART busy.

LD3:
  CRC encoder running.

LD4-LD7:
  Fixed 1000 marker for tracker frame encoder.
```

UART
----

```text
Connector:
  J13

PC port:
  Usually COM6, but confirm in Windows Device Manager.

Baud:
  115200

Data:
  8 data bits, no parity, 1 stop bit, flow control none
```

Pass condition
--------------

```text
1. Bitstream programs successfully.
2. PuTTY/TeraTerm receives p1fe lines on the J13 UART COM port.
3. seq increments once per report.
4. pay_b=00129.
5. frame_b=00133.
6. pre=A55A.
7. crc is two hex characters.
8. crc_ok=1.
9. ok=1.
```

Result
------

```text
PASS
```

Observed output:

```text
p1fe,seq=00015,payload=trk,pay_b=00129,frame_b=00133,pre=A55A,crc=FA,crc_ok=1,ok=1
p1fe,seq=00016,payload=trk,pay_b=00129,frame_b=00133,pre=A55A,crc=44,crc_ok=1,ok=1
p1fe,seq=00017,payload=trk,pay_b=00129,frame_b=00133,pre=A55A,crc=D3,crc_ok=1,ok=1
p1fe,seq=00018,payload=trk,pay_b=00129,frame_b=00133,pre=A55A,crc=9B,crc_ok=1,ok=1
p1fe,seq=00019,payload=trk,pay_b=00129,frame_b=00133,pre=A55A,crc=0C,crc_ok=1,ok=1
p1fe,seq=00020,payload=trk,pay_b=00129,frame_b=00133,pre=A55A,crc=0C,crc_ok=1,ok=1
p1fe,seq=00021,payload=trk,pay_b=00129,frame_b=00133,pre=A55A,crc=9B,crc_ok=1,ok=1
p1fe,seq=00022,payload=trk,pay_b=00129,frame_b=00133,pre=A55A,crc=25,crc_ok=1,ok=1
```

Confirmed:

```text
seq increments once per report.
pay_b=00129.
frame_b=00133.
pre=A55A.
crc is generated as two hex characters.
crc_ok=1.
ok=1.
```

Note:

```text
seq 00019 and 00020 both produce crc=0C. This is acceptable because CRC-8 is one
byte and collisions can happen. The pass condition is crc_ok=1.
```

--------------------

```text
Feed the generated tracker frame status into the OFDM payload placer, so one
board test reports both frame encoding and OFDM placement in the same line.
```
