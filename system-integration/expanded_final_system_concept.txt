Expanded Final System Concept
=============================

Working title
-------------

```text
FPGA-Orin Renewable Edge Telemetry Gateway with Reliable Communication and Network Monitoring
```

Core idea
---------

Build a small but realistic renewable-energy edge system:

```text
Solar / battery / sensors
  -> Nexys Video FPGA real-time controller and telemetry gateway
  -> reliable digital communication layer
  -> Orin Nano Super edge supervisor
  -> network/cloud/site dashboard
```

The system should show:

```text
1. Renewable energy monitoring/control.
2. FPGA-based real-time logic.
3. Digital communication reliability.
4. Networked telemetry/dashboarding.
5. Orin-based edge intelligence.
```

Role split
----------

Nexys Video FPGA:

```text
Real-time field layer.

Responsibilities:
  - read voltage/current sensors
  - calculate power
  - generate PWM
  - run MPPT/protection logic
  - create stable telemetry packets
  - add sequence counter and checksum/CRC
  - validate local sensor/communication links
  - provide deterministic timing
  - act as the hardware gateway between renewable hardware and Orin/PC
```

Important:

```text
The FPGA is not only a passive bridge.
It is the deterministic controller and first safety/protection layer.
```

Orin Nano Super:

```text
Edge supervisor and network brain.

Responsibilities:
  - receive telemetry from FPGA
  - validate packet sequence/checksum
  - log CSV/JSON/database data
  - run dashboard
  - monitor communication correctness
  - detect abnormal solar/battery behavior
  - send selected data to a site/server/cloud
  - optionally run AI/camera analysis for shading/soiling
  - optionally choose high-level commands for FPGA
```

Important:

```text
The Orin can make supervisory decisions, but the FPGA should still own fast PWM,
protection, and sensor timing.
```

Digital communication role
--------------------------

Digital communication should cover the reliability of data movement, not just RF modulation.

In this project, digital communication means:

```text
1. Sensor-to-FPGA links:
   SPI / I2C / UART sensor data integrity.

2. FPGA packet layer:
   framing, sequence counter, checksum/CRC, packet loss detection.

3. FPGA-to-Orin/PC link:
   UART first, SPI/Ethernet later.

4. Reliability experiments:
   corrupted packet detection, BER/frame error simulation, QPSK/OFDM model later.
```

Best practical definition:

```text
fpga-digital-communications studies how to move the renewable telemetry packet reliably.
```

Network role
------------

Networking should move the validated telemetry to a useful destination.

In this project, networking means:

```text
1. Orin/PC receives FPGA telemetry.
2. Orin/PC exposes the data through a local dashboard or API.
3. Orin/PC can send data to a remote site/server/cloud.
4. Network layer tracks packet rate, packet loss, delay, and fault status.
5. network-telemetry-dashboard parses/logs/monitors these packets.
```

Possible network targets:

```text
MVP:
  Local dashboard on Orin/PC.

Next:
  Local web server on Orin.

Later:
  MQTT broker, HTTP API, WebSocket dashboard, or cloud database.

Portfolio-safe:
  Local site/dashboard first, then optional cloud upload.
```

Battery and solar state
-----------------------

Useful fields to monitor:

```text
Solar:
  - voltage
  - current
  - power
  - energy generated over time
  - duty cycle
  - MPPT state
  - fault flags

Battery, first as simulation:
  - voltage
  - current
  - estimated state of charge
  - charge/discharge state
  - overvoltage/undervoltage warning
```

Measured storage direction:

```text
Add a protected 1S LiPo/Li-ion battery only as a measured storage device at first.
Do not use it as the supply for Nexys Video or Orin.

The stronger project story is:
  solar panel state
  battery/storage state
  light/sun-tracking sensor state
  protection state
  communication integrity
  network delivery status

All of those become one renewable edge-system report.
```

Safety note:

```text
Do not directly charge lithium batteries without a proper charger/BMS.
Start with battery simulation or a safe low-voltage emulator.
```

Optional sun-tracking extension
-------------------------------

Solar angle control can make the project richer, but it adds mechanical complexity.

Recommended path:

```text
Stage 1:
  Simulate sun angle and panel angle in software.

Stage 2:
  Use small servo/motor with no real solar load.

Stage 3:
  Add light sensors or camera/Orin vision for shading/sun direction.

Stage 4:
  Compare fixed panel vs tracking energy in logs.
```

Where control should live:

```text
Orin:
  High-level sun-tracking decision or camera/light analysis.

FPGA:
  Deterministic servo/PWM timing and safety limits.
```

Best final architecture
-----------------------

```text
Solar/Battery side
  -> sensors
  -> FPGA:
       sample/filter
       power calculation
       MPPT/PWM/protection
       packet creation with seq/checksum
       servo/PWM timing later
  -> digital communication layer:
       packet integrity
       BER/frame error checks
       reliability metrics
  -> Orin:
       parser/logger/dashboard
       network service
       AI/fault/shading analysis
       optional sun-tracking decision
  -> network:
       local dashboard first
       optional site/cloud later
```

Recommended project evolution
-----------------------------

```text
Current:
  FPGA shared packet v1 works using fake switch data.

Next:
  PC parser/logger validates seq and checksum.

Then:
  Orin/PC dashboard shows live telemetry and energy estimate.

Then:
  Digital communication project uses the same packet for reliability tests.

Then:
  Network project sends the same packet to a local dashboard/API.

Then:
  Real voltage/current sensor path replaces fake values.

Then:
  MPPT fake-control becomes real low-voltage control.

Optional final extension:
  battery state simulation and simple sun-tracking demo.
```

Final demo story
----------------

```text
The FPGA collects and controls renewable energy data in real time.
It packetizes telemetry with sequence and checksum fields.
The Orin validates, logs, visualizes, and forwards this data over a network.
The communication layer measures packet correctness and reliability.
The network layer publishes and monitors the telemetry stream.
The same data path can later support battery state estimation and sun-tracking control.
```

Why this is stronger for CV
---------------------------

```text
It combines:
  - renewable energy
  - FPGA real-time control
  - embedded telemetry
  - digital communication reliability
  - network monitoring
  - edge AI/dashboarding with Orin

This fits the target identity:
  computer engineering + renewable energy systems
  supported by strong digital communication
  supported by basic networking
```
