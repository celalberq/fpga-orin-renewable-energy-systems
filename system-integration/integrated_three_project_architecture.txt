Integrated Three-Project Architecture
=====================================

Purpose
-------

The three summer projects should share one base platform instead of becoming three unrelated demos.

For the full theory, hardware roles, and step-by-step build doctrine, use:

```text
system_theory_and_build_doctrine.txt
```

Core idea:

```text
Renewable energy data is collected from the PV/solar side.
The FPGA controls/samples/formats the data.
Digital communication methods make the data movement reliable/measurable.
Networking methods move the data toward PC/Orin dashboards and infrastructure monitoring.
```

Shared base platform
--------------------

```text
Nexys Video FPGA
  -> reads or generates solar telemetry
  -> runs real-time PWM/control/protection
  -> formats telemetry packets
  -> sends packets through UART first
  -> later sends packets through stronger digital comm and Ethernet/network paths

PC first, Orin later
  -> reads telemetry
  -> logs data
  -> displays dashboard
  -> runs analysis/fault detection
```

Project roles
-------------

solar-tracker-bess: Renewable energy / solar

```text
Main data source and control project.

Responsibilities:
  - PV voltage/current/power data
  - PWM duty
  - MPPT state
  - fault/protection flags
  - safe low-voltage solar/BESS demo path
```

fpga-digital-communications: Digital communication

```text
Reliable telemetry communication project.

Responsibilities:
  - frame format
  - sequence counter
  - CRC/checksum
  - QPSK/OFDM simulation later
  - BER/error counters
  - reliability comparison for the same solar telemetry data
```

network-telemetry-dashboard: Network

```text
Infrastructure/network telemetry project.

Responsibilities:
  - packet parsing
  - UDP/Ethernet-style metadata
  - dashboard/logging path
  - network monitoring for the same solar telemetry stream
  - later Orin/PC network service
```

Shared telemetry packet v1
--------------------------

Use one packet shape across all projects:

```text
p3,seq=00001,d_pct=00050,v_mv=14560,i_ma=01268,p_mw=18462,mppt=up,f=0,chk=CC,raw=80
```

Fields:

```text
project id:
  p3 for renewable source.
  Later p1 and p2 can wrap, test, transmit, or parse this same data.

seq:
  packet sequence counter.

d_pct:
  PWM duty percentage.

v_mv:
  voltage in millivolts.

i_ma:
  current in milliamps.

p_mw:
  power in milliwatts.

mppt:
  MPPT direction/state.

f:
  fault flag.

chk:
  simple checksum for communication and network validation.
  Later this can be upgraded to a stronger CRC.

raw:
  raw 8-bit duty command, included so PC/Orin can validate chk.
```

Why this is better
------------------

```text
1. solar-tracker-bess becomes the main Australia-facing renewable/computer project.
2. fpga-digital-communications becomes useful because it improves the reliability of real telemetry data.
3. network-telemetry-dashboard becomes useful because it moves and monitors the same telemetry data.
4. The CV story becomes one integrated engineering system, not three random projects.
5. The same FPGA board and future Orin Nano Super are justified across all projects.
```
