Solar Tracker and BESS Telemetry Format V1
==========================

Purpose
-------

Move from raw fake hex telemetry to engineering-style fields that look like a real
solar/BESS/SCADA monitoring packet.

Packet
------

```text
p3,seq=00001,d_pct=00050,v_mv=14560,i_ma=01268,p_mw=18462,mppt=up,f=0,chk=CC,raw=80
```

Fields
------

```text
p3:
  Project identifier.

seq:
  Packet sequence counter.
  Fixed width: 5 decimal digits.

raw:
  Raw 8-bit switch/duty command in hexadecimal.
  This is included so the PC/Orin can validate chk.

d_pct:
  PWM duty percentage.
  Fixed width: 5 decimal digits.
  Range in this board-only test: 00000 to 00100.

v_mv:
  Fake PV/input voltage in millivolts.
  Fixed width: 5 decimal digits.
  Range in this board-only test: 12000 to 17100.

i_ma:
  Fake current in milliamps.
  Fixed width: 5 decimal digits.
  Range in this board-only test: 00500 to 02030.

p_mw:
  Fake power in milliwatts.
  Fixed width: 5 decimal digits.
  Calculated from v_mv and i_ma.

f:
  Fault flag.
  0 = normal.
  1 = duty command is very high in this board-only test.

mppt:
  Compact MPPT result/state field.
  up = estimated power increased compared with the previous packet.
  dn = estimated power decreased compared with the previous packet.
  hd = estimated power held steady.

chk:
  Temporary 8-bit XOR checksum over the packet numeric/state fields.
  This is not the final polynomial CRC yet.
```

Temporary scaling for board test 02
-----------------------------------

```text
duty_raw = SW0-SW7
d_pct    = zero_extend(duty_raw) * 100 / 255
v_mv     = 12000 + duty_raw * 20
i_ma     = 500 + duty_raw * 6
p_mw     = v_mv * i_ma / 1000
f        = 1 when duty_raw >= 0xF0
mppt     = up/dn/hd based on power movement from previous packet
chk      = XOR of seq, duty, voltage, current, power, fault, and mppt code
```

Implementation note:

```text
duty_raw must be widened before multiplying by 100.
If the multiply is left as 8-bit arithmetic, d_pct can stay stuck at 00000 even though
the other switch-derived fields change correctly.
```

Shared packet use:

```text
solar-tracker-bess:
  Generates the renewable telemetry packet.

fpga-digital-communications:
  Uses this packet as the payload for digital communication reliability tests.

network-telemetry-dashboard:
  Uses this packet as the payload for network parsing/logging tests.
```

Storage telemetry extension
---------------------------

Keep packet v1 stable for the current tests. After real PV sensing is passing,
create packet v2 for measured storage:

```text
p3v2,seq=00001,d_pct=00050,pv_mv=14560,pv_ma=01268,pv_mw=18462,
     bv_mv=03920,bi_ma=00120,bsoc=00070,bstate=chg,mppt=up,f=0,chk=CC
```

Added battery/storage fields:

```text
bv_mv:
  Battery voltage in millivolts.

bi_ma:
  Battery current in milliamps.
  Positive means charging, negative/discharge can be represented later with a
  direction field if the FPGA packet stays unsigned.

bsoc:
  Estimated battery state of charge in percent.

bstate:
  chg = charging
  dis = discharging
  idl = idle
  low = low battery warning
  prt = protection active
```

This makes the same telemetry packet useful for renewable control, digital
communication reliability tests, and network/system reporting.

Later replacement
-----------------

```text
v_mv:
  Replace fake switch-derived value with calibrated voltage sensor/ADC result.

i_ma:
  Replace fake switch-derived value with calibrated current sensor/ADC result.

p_mw:
  Keep calculated on FPGA or PC from measured v_mv and i_ma.

f:
  Replace temporary duty threshold with real protection flags:
    over-voltage
    over-current
    sensor fault
    PWM disabled
    emergency stop
```
