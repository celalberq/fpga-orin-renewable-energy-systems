Proje2 Network Test 09: Tracker Bridge Reliability Warning/Recovery
===================================================================

Status
------

```text
PASS - live tracker bridge warning/recovery run
```

Goal
----

Demonstrate that the live integrated system can detect packet loss/corruption,
raise a dashboard warning, and then recover after clean packets resume.

This is stronger than the earlier reliability proxy test because it keeps the
full project chain:

```text
proje3 Orin tracker
  -> proje1 CRC/QPSK/OFDM bridge metadata
  -> proje2 reliability proxy fault injection
  -> proje2 dashboard link health and recovery
```

PC Terminal 2: Reliability Proxy
--------------------------------

This injects faults only during the first 30 received packets, then returns to
clean forwarding. That lets the dashboard show warning first and recovered later.

```powershell
cd "C:\Users\Msi\Documents\yaz proje"
python proje2/code/pc_app/solar_reliability_proxy.py --bind-host 0.0.0.0 --bind-port 5012 --forward-host 127.0.0.1 --forward-port 5011 --drop-every 7 --corrupt-every 9 --inject-first 30 --log proje2/data/solar_reliability_proxy_bridge_log.csv
```

Expected Warning Phase
----------------------

During the first 30 packets:

```text

  Sequence Gaps increases
```

Expected Recovery Phase
-----------------------

After packet 30, the proxy stops injecting faults.

After 10 clean recent packets:

```text
Dashboard:
  Link State = recovered
  Recent telemetry is clean
  Invalid Packets and Sequence Gaps still show the historical fault count
  Digital Comm Layer remains CRC/QPSK/OFDM
```
