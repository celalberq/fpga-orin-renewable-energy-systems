Why this exists
---------------

This test originally kept the project moving while the physical pan/tilt
mechanism was not ready. It still matters because it proves the tracking
controller, telemetry packet, network path, dashboard, and logging without
requiring motor movement.

Data path
---------

```text
Virtual sun / simulated four-LDR sensor
  -> Orin software tracking loop
  -> UDP JSON packet
  -> proje2 dashboard
```

Optional real sensor mix:

```text
INA226 real voltage/current/power can be included with --ina-enable.
Servo movement can be enabled later with --drive-servos.
Default mode does not move servos.
```

Expected dashboard result
-------------------------

```text
Source: Orin software solar tracker
Link State: healthy
Tracker State: seeking, then locked when angle error is small
Panel Angles: simulated pan/tilt position

Tracking Error: angle difference between panel and light

```

Run tracker plus real INA226 values
-----------------------------------

Use this after the basic software tracker works:

```text
python3 proje3/code/orin_app/tracker_softloop_udp_gateway.py --udp-host PC_IP_ADDRESS --udp-port 5011 --ina-enable --ina-bus 7 --ina-addr 0x44 --shunt-ohms 0.1
```

Expected behavior:

```text
Tracker fields come from the software loop.
Voltage/current/power come from the real INA226 solar sensor.
```

Servo tracker mode
------------------

Use this only after the mechanism is stable:

```text
python3 proje3/code/orin_app/tracker_softloop_udp_gateway.py --udp-host PC_IP_ADDRESS --udp-port 5011 --drive-servos --pca-bus 7 --pca-addr 0x40 --pan-channel 15 --tilt-channel 12 --pan-min 70 --pan-max 110 --tilt-min 80 --tilt-max 100
```

Safety:

```text
Do not use --drive-servos until the new bracket moves freely by hand.
If a servo buzzes or hits a stop, unplug the 5V servo adapter.
Keep common ground between Orin and PCA9685.
```
