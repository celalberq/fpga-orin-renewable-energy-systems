Goal
----

Read the Nexys four-LDR UART packet directly on the Orin and control the
replacement pan/tilt mechanism through the PCA9685.

Geometry correction
-------------------

The narrow live test proved sensing, filtering, servo polarity, and movement,
but the upward-facing platform exposed a kinematic error in the original
controller assumption. Pan rotation around the panel normal initially spins the
panel in its own plane; it does not directly change the panel incidence angle.

Correct control sequence:

```text
1. align-pan: rotate azimuth until corrected horizontal LDR error is centered
2. track-tilt: change elevation only after the light lies in the tilt plane
3. locked: hold both axes when horizontal and vertical errors are in deadband
```

`ldr_servo_tracker.py` now defaults to `--control-mode altaz`. The previous
simultaneous behavior remains available as `--control-mode cartesian` only for
a mechanism whose two axes directly change local horizontal and vertical aim.

Do not use the expanded-range command until pan cable clearance has been tested
manually. A light source located directly to the panel's side can require close
to 90 degrees of azimuth rotation before tilt can point toward it.

First alt-az phase result and correction
----------------------------------------

```text
Calibration packets: 12141 through 12160
Calibration noise: horizontal 0.076%, vertical 0.099%
Pan movement and align-pan phase: PASS
Tilt movement: BLOCKED BY PHASE CHATTER
```

At packet 12165, corrected horizontal error entered the 0.7% lock deadband and
the controller selected `track-tilt`. The next packet returned to `align-pan`,
so the two-consecutive-sample movement gate never allowed tilt to move.

Correction:

```text
Enter track-tilt when absolute horizontal error is below 2%.
Stay in track-tilt until horizontal error exceeds 4%.
Use the original 0.7% deadband only for final lock and tilt error.
```

This hysteresis preserves pan-first sequencing without starving the tilt axis.


Upper-quadrant pan-direction correction
---------------------------------------

After moving the LDRs closer to the center divider, live testing showed that
lower-left and lower-right targets tracked correctly, while top-left and
top-right selected the opposite azimuth direction. In an azimuth/elevation
mechanism, the pan correction reverses across the sensor's vertical hemisphere:

```text
lower-left:  negative pan correction
lower-right: positive pan correction
top-left:    positive pan correction
top-right:   negative pan correction
```

The Orin controller now applies this hemisphere correction only to alt-az pan
movement. Cartesian mode and tilt polarity are unchanged.

Bounded pan/tilt phase scheduling
---------------------------------

Powered single-axis testing confirmed that both servos, PCA9685 channels, and
mechanical axes work across an obvious commanded range. A subsequent automatic
run showed that tilt commands were rare because `align-pan` could run until a
pan endpoint whenever the horizontal/vertical error ratio stayed outside the
angular threshold.

Alt-az scheduling is now bounded:

```text
Maximum continuous align-pan window: 8 sensor samples
Guaranteed track-tilt window: 6 sensor samples while vertical error is active
```

After the tilt window, the controller may return to pan alignment if needed.
This alternating coordinate correction prevents either working axis from
starving the other while retaining pan-first behavior.

Dominant-error controller
-------------------------

The preferred live controller now selects whichever corrected normalized LDR
axis has the larger error. To prevent rapid switching, the current axis keeps
control until the other exceeds it by 5 percentage points by default:

```text
Control mode: dominant
Default switch margin: 0.05 (5 percentage points)
At servo endpoint: immediately offer control to the other active axis
Final lock deadband: unchanged
```

The previous bounded `altaz` mode remains available for comparison. Dominant
mode still applies the verified upper/lower hemisphere correction to pan.

Latched sequential continuous controller
----------------------------------------

Live dominant-mode testing showed undesirable decisions near the mechanical
limits. The replacement `sequential` mode chooses the larger error only when a
new correction cycle starts. It then commits to that axis until its corrected
error enters the deadband or crosses the calibrated center. Only then does it
switch to the other axis.

After both errors enter the deadband, the state is `locked`. Every subsequent
sensor packet is still evaluated; movement automatically resumes when either
error leaves the deadband, which supports continuous solar tracking. If errors
remain but neither requested servo direction is available, the reported state
is `blocked-limits`, not `locked`.

Fixed LDR mounting correction
-----------------------------

The installation photo confirmed that the four-LDR cross is stationary on the
table beside the independently moving servo head. Feedback modes that expect
servo motion to change LDR error are therefore not valid for this setup.

`--sensor-mount fixed` now maps the stationary LDR direction to absolute servo
targets. Centered light explicitly targets pan 90 and tilt 90. Pan is derived
from the LDR error-vector bearing, while tilt offset is derived from radial LDR
error. A 5% vertical hemisphere hysteresis prevents representation chatter near
the left/right boundary. Servo axes approach these targets sequentially and
automatically recalculate them on every packet for continuous tracking.

Final live result: user reported perfect tracking. Pan and tilt follow the fixed
four-LDR direction, return to 90/90 when the light returns to calibrated center,
and resume correction when the light moves again.
